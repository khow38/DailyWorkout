# DailyWorkout / FORM

무료 맨몸 운동 루틴 생성기 및 기록 앱입니다. **`index.html`을 브라우저에서 열면 바로 실행됩니다.** 앱에는 설치, 빌드, 계정, 외부 API 또는 인터넷 연결이 필요하지 않습니다. CSS, JavaScript, 3D 렌더러, 사람형 모델과 관절 모션 데이터가 약 4.3MB의 HTML 한 파일에 포함되어 있습니다. 3D 시범에는 WebGL 2를 지원하는 브라우저가 필요합니다.

## 사용 방법

1. **Routine**에서 운동 수준, 주당 횟수, 장비, 목표를 선택합니다.
2. **Start this workout**을 누릅니다. 준비 운동부터 마무리 스트레칭까지 안내합니다.
3. 실제 수행한 반복 횟수 또는 유지 시간과 RPE를 입력하고 **Log**로 세트를 기록합니다.
4. **Save & finish**로 전체 또는 부분 완료 기록을 저장합니다.
5. 목표 상한, 목표 이하 RPE, 올바른 자세 조건을 충족하면 다음 난도 제안을 확인하고 선택할 수 있습니다.

3일 전신, 4일 상·하체, 6일 푸시·풀·하체 분할을 지원합니다. 장비 없는 등 운동은 풀업/로우를 대체하지 못한다는 한계를 앱에 표시합니다. 스킬 목표는 손 균형 또는 L-sit/압축 훈련입니다.

## 내 체형의 3D 운동 가이드

- Routine 마지막 단계의 **캐릭터 설정**, 운동 화면의 **캐릭터 꾸미기**, 또는 설정의 **캐릭터 꾸미기 · 체형**에서 편집기를 엽니다. 편집기 위에서 **남성 / 여성** 베이스 모델을 선택합니다. **체형** 탭에서 키, 몸무게, 어깨/허리/골반 너비, 가슴·흉곽 볼륨, 다리 비율, 피부 톤을 입력합니다. 베이스 변경은 현재 키·체형·외모 조절값을 유지하며 운동 난도나 목표를 바꾸지 않습니다. 입력한 설정은 이 브라우저에만 저장됩니다. 루틴 작성 중 변경한 캐릭터는 루틴 생성 시 함께 저장됩니다.
- 각각 별도 형상과 피부 가중치를 가진 남성·여성 베이스 메시를 같은 65개 관절 체계로 부드러운 피부 명암과 몸체 외곽선으로 렌더링합니다. 체형은 바인드 메시와 골격을 함께 변형한 후 다시 바인딩합니다. 키·몸무게만으로 신체를 측정하거나 복제하지 않으며, 비율 슬라이더로 닮은 체형을 맞추는 방식입니다.
- 43개 운동 각각에 **17개 키프레임 × 65개 joint의 회전 입력값**이 있습니다. 부모 관절 기준의 quaternion을 보간하고, 기준 모션의 월드 회전 변화량을 선택한 모델의 바인드 축으로 리타기팅해 기본 포즈를 재생합니다. 이어서 체형별 팔·다리는 길이를 유지하는 해석적 2본 IK로 보정합니다. 팔꿈치/무릎 굽힘 방향과 한계를 제한하며 바닥/기구 접점, 무릎 접점을 유지하도록 골반 위치를 반복 보정합니다.
- 팔꿈치 1–150도, 무릎 1–155도 범위 안에서 동작하며, 일부 동작은 더 좁은 범위를 사용합니다. 손목 굽힘과 하퇴–발 축의 방향도 제한합니다. 이 값은 캐릭터용 제약이며 개인의 정상 가동 범위를 진단하는 기준이 아닙니다.
- 팔의 높이와 도달 방향에 맞춰 어깨뼈의 상방 회전/전인을 제한된 범위에서 연결합니다. 몸통, 목, 어깨 높이와 손가락 그립은 운동별로 조절합니다. 근육 힘, 충돌, 균형을 모두 계산하는 생체역학 시뮬레이터나 모션 캡처는 아닙니다.
- 드래그 회전, 정면/측면/사선 보기, 재생/정지, 0.25×/0.5×/1× 재생, 구간 슬라이더, 관절/접점 표시를 제공합니다. 동작 줄이기를 설정한 브라우저에서는 자동 재생하지 않습니다. 시범은 자세 설명과 함께 참고하세요.
- 운동 화면의 **관절 회전값 · 65 joints**를 펼치면 현재 구간에서 선택 모델로 리타기팅한 입력값과 IK 적용 후 값을 비교할 수 있습니다. 표시되는 X/Y/Z는 바인드 포즈 대비 로컬 Euler 각도이며 의료적 굴곡각과 같지 않습니다. 실제 회전 저장·보간은 quaternion으로 처리합니다.
- 이전 저장 데이터에는 기본 체형을 적용하므로 기록을 초기화할 필요가 없습니다. 체형 변경은 운동 기록이나 진행 중 타이머를 바꾸지 않습니다.

모델 및 라이선스 출처는 [THIRD_PARTY.md](THIRD_PARTY.md)에 기록했습니다.

## 캐릭터 스튜디오

**프리셋 → 얼굴 → 헤어 → 스타일 → 체형** 순서로 선택하거나 원하는 탭부터 편집할 수 있습니다.

- 남녀별 실제 렌더링 미리보기를 가진 네 가지 외모 프리셋 ONYX / LUMI / SION / AERI. 프리셋은 외모만 바꾸며 키·몸무게·체형을 유지합니다.
- **균형형 / 소프트형 / 선명형 / 하트형** 기본 얼굴형을 먼저 선택합니다. 기존 히어로 얼굴을 제거하고 새로 작성한 얼굴 표면, 눈꺼풀, 눈동자, 눈썹, 코와 입술을 사용합니다.
- 얼굴 길이/너비/부드러움, 턱 너비/길이, 광대, 눈 크기/간격/눈꼬리/뜨임, 콧대/코 너비/길이, 입 너비/입술 볼륨, 눈썹 높이/두께를 실제 메시 변형으로 조절합니다. 눈동자/입술 색도 변경할 수 있습니다.
- 사이드 파트, 센터 파트, 숏 크롭, 레이어드 보브, 롱 레이어, 트윈 번 및 헤어 없음. CC0 헤어 메시 4종에서 길이와 볼륨을 조절한 선택지를 제공합니다. 볼륨/색상을 조절할 수 있고 헤어·눈동자·이어 스터드는 Head joint를 따라 움직입니다.
- 운동복 스타일 3종과 상의/하의/슈즈 색상, 실버/골드 이어 스터드를 선택할 수 있습니다. 운동복은 몸에 맞는 재질 표현이며 별도의 옷감 물리 시뮬레이션은 없습니다.
- **얼굴** 확대, **전신**, **운동 보기**로 외모와 스쿼트 동작을 확인합니다. **캐릭터 저장**을 눌러 확정하며 **취소**는 편집 내용을 버립니다. 저장 전에는 실제 설정을 덮어쓰지 않습니다.

별도 남성·여성 베이스 메시를 사용하며 양쪽 모두 모든 프리셋과 편집 기능을 사용할 수 있습니다. 새 얼굴은 피부 가중치로 Head/neck 관절에 연결하며 원래 목의 절단 경계에 위치·법선·가중치를 맞춥니다. 눈·코·입과 헤어는 같은 얼굴 길이/너비 변환을 사용합니다. 남녀의 바인드 위치 차이를 보정하고 피부색과 명암을 몸체와 일치시킵니다. 현재 표현은 단순화한 스타일의 3D 캐릭터이며 고해상도 게임 캐릭터 수준의 얼굴 에셋은 아닙니다. 특정 상용 게임의 캐릭터 에셋을 사용하지 않으며, 얼굴 캡처·종족별 골격·헤어 물리·표정 리깅은 포함하지 않습니다. 얼굴·헤어·색상 변경은 관절 계층/길이와 원본 모션 데이터를 바꾸지 않습니다. 베이스 모델과 체형 변경은 골격 길이 및 접촉 샘플을 다시 측정하고 메시를 다시 바인딩하며, 관절 축 리타기팅과 IK를 통해 원본 모션을 적용합니다. 기존 저장 데이터는 남성 베이스로 읽히며 새로운 외모 항목만 기본값이 채워집니다.

## 데이터와 타이머

- 설정, 루틴, 진행 중 세션, 기록은 현재 브라우저의 `localStorage`에 저장됩니다.
- 파일 주소의 저장 동작은 브라우저마다 다릅니다. 안정적인 사용에는 동일한 로컬 주소를 유지하세요. Python이 설치되어 있다면 프로젝트 폴더에서 `python -m http.server 8080 --bind 127.0.0.1`을 실행하고 `http://127.0.0.1:8080`을 여세요.
- 파일 직접 열기와 로컬 서버는 서로 다른 저장소를 사용합니다. 브라우저/기기 간 자동 동기화는 없습니다.
- 설정의 **Export all workout data**는 읽을 수 있는 JSON 백업을 다운로드합니다. 앱 내 백업 가져오기 기능은 포함하지 않습니다.
- 저장이 차단되거나 용량이 부족하면 화면에 표시합니다. 이때 데이터는 탭 메모리에 남으므로 종료 전에 내보내세요.
- 손상된 저장 데이터는 자동으로 덮어쓰지 않습니다. 설정에서 원본을 내보내거나 명시적으로 초기화할 수 있습니다.
- 타이머는 종료 시각을 저장하므로 새로고침 후에도 이어집니다. 앱이 닫혀 있거나 기기가 잠긴 상태에서 알람을 보장하지 않습니다. 소리는 브라우저의 사용자 상호작용/오디오 정책을 따릅니다.
- 동시 편집을 피하기 위해 다른 탭에서 데이터가 바뀌면 최신 데이터로 새로고침하도록 안내합니다.
- 반복 횟수와 유지 시간은 별도로 합산합니다. 좌우 운동의 반복 횟수는 한쪽 기준이며 두 쪽을 수행합니다. 연속 운동일은 최소 한 개의 본 운동/스킬 세트를 기록한 현지 날짜를 기준으로 계산합니다.

## 검증

앱 실행에는 Node.js가 필요하지 않습니다. 아래는 3D 소스 수정 후 단일 HTML을 다시 묶고 검사하는 개발 명령입니다.

```powershell
npm ci
npm run build
npm test
npm run test:avatar
```

테스트는 Windows에 설치된 Chrome 또는 Edge를 사용합니다. 설치된 브라우저를 찾을 수 없는 환경에서는 `npx playwright install chromium`을 먼저 실행하세요. `BROWSER_PATH` 환경 변수로 실행 파일을 지정할 수도 있습니다. 임시 로컬 HTTP 서버와 격리된 브라우저 저장소를 사용하며 실제 운동 기록은 변경하지 않습니다.

테스트 범위: 288개 프로필 조합의 장비 적합성, 단계별 입력, 세트 기록, 새로고침 복구, 타이머 일시정지/재개/완료, 부분/전체 저장, 진행 규칙, 난도 하향, 모바일 오버플로, 잘못된 저장 데이터, 오프라인 파일 실행. 아바타 검사는 모든 키프레임의 65개 회전값/정규화/루프 연결과, 키프레임 사이를 보간한 남녀 2개 베이스 × 5가지 체형 × 43개 운동 × 16개 구간(6,880개 자세)의 뼈 길이, 관절 제한, 접점 오차, 원본 모델 불변성을 확인합니다. 브라우저에서 남녀 모델 각각의 모든 운동 WebGL 렌더링, 외모 프리셋의 실제 메시 변형과 골격 보존, 기본 얼굴형 4개와 헤어 7개 선택, 남녀별 프리셋 미리보기, 얼굴 피부 가중치와 운동 중 목 접합부, 얼굴/컬러/운동복 편집, 저장/취소/복구, 관절 표, 시점/재생 제어, 320px 화면과 외부 네트워크 요청이 없음을 검사합니다. 시뮬레이션 접점 검사는 실제 운동 자세의 임상 검증을 의미하지 않습니다.

## 구현 구조

`index.html` 안에서 스타일, 운동 progression matrix, 프로필 검증/저장, 루틴 생성, 화면 렌더링, 세션/타이머 이벤트를 순서대로 구분합니다. 운동 세션은 계획의 스냅샷을 저장하므로 나중에 계획을 바꾸어도 기존 기록이 바뀌지 않습니다. 추천은 결정적인 규칙 기반이며 외부 AI 모델을 호출하지 않습니다.

3D 소스는 `src/kinematics.js`(체형/골격/관절 제한/접점), `src/motions.js`(운동별 작성 경로), `src/joint-poses.js`(전체 관절 포즈 보간 및 모델별 바인드 축 리타기팅), `src/appearance.js`(외모 설정/프리셋/운동복 재질), `src/portrait.js`(원본 머리 절단/새 얼굴 조형/눈·입술/헤어/목 스키닝), `src/creator-ui.js`(편집 폼), `src/avatar.js`(렌더러/시점/재생/자원 해제)로 분리합니다.

`assets/motion-clips.json`이 재생에 사용하는 전체 관절 입력 데이터입니다. joint 이름/parent/bindRotation과 운동별 duration/frames/rotations/clavicleOffsets가 들어 있습니다. 단위는 m와 부모 기준 quaternion `[x,y,z,w]`, 월드 축은 Y-up입니다. `npm run build`는 입력값의 완결성/회전 정규화/시간 순서를 검증하고 모델과 함께 HTML의 `FORM_AVATAR_START`/`FORM_AVATAR_END` 구간에 묶습니다. 모션 JSON을 덮어쓰지 않으므로 직접 수정한 회전 입력도 유지됩니다.

기준 모션의 초기 입력값은 `src/motions.js`의 운동별 경로를 제약 IK로 계산해 만들었습니다. 경로로부터 다시 생성할 때만 `npm run bake:motions`를 실행하세요. 이 명령은 모션 JSON의 수동 편집을 덮어씁니다. 모션은 실제 사람에게서 캡처한 자료가 아닙니다. 여성 원본 glTF를 다시 묶으려면 `node scripts/import-character.mjs <원본.gltf> assets/character-female.glb`를 사용합니다. 이 변환은 원본 형상·스키닝을 보존하고 외부 텍스처 참조를 앱의 재질로 교체합니다. 헤어 원본을 다시 변환하려면 `node scripts/import-hair.mjs <원본 glTF/bin 폴더>`를 사용합니다. 얼굴·헤어를 수정한 뒤 프리셋 미리보기를 갱신할 때는 `npm run build`, `npm run bake:portraits`, `npm run build` 순서로 실행합니다. 미리보기는 실제 WebGL 렌더러에서 생성하며 앱 실행 중 추가 네트워크나 렌더러를 요구하지 않습니다.

앱 실행에는 `assets/`, `src/`, `node_modules/` 폴더가 필요하지 않습니다.

일반적인 저항 운동 원칙은 [ACSM 2026 position stand](https://pmc.ncbi.nlm.nih.gov/articles/PMC12965823/)를 참고했습니다. 앱의 구체적인 반복 범위와 진행 문턱은 구현상 선택이며 임상 처방은 아닙니다.
